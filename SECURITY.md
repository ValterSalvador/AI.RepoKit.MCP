# Security Policy

## Supported Versions

AI.RepoKit's published v3.0.0 release is available through
GitHub Releases.

The planned public v4.0.0 release is still in preparation.

A formal security-support and end-of-life policy has not yet
been approved. The availability of historical releases does
not imply a security maintenance commitment.

The support policy is tracked under:
https://github.com/ValterSalvador/AI.RepoKit.MCP/issues/77

## Reporting a Vulnerability

Private vulnerability reporting is enabled for this repository.

Please use the GitHub Security Advisories page:

https://github.com/ValterSalvador/AI.RepoKit.MCP/security/advisories

Select "Report a vulnerability" to submit a private report.

Do not open public issues, pull requests, or discussions
containing undisclosed vulnerability details.

Never include actual credentials, access tokens, private keys,
or other secrets in reproduction materials.

## Information to Include

When possible, provide:

- Affected product version and component.
- Operating system and architecture.
- Relevant configuration and prerequisites.
- Minimal, safe reproduction steps.
- Expected and observed behavior.
- Potential security impact.
- Known mitigations or workarounds.

Remove sensitive information before submitting evidence.

## Scope and Security Boundaries

AI.RepoKit includes local repository tooling, MCP features,
agent execution abstractions, and internal workflow components.

Implementation in source code does not imply that a component
is included in a public distribution.

Security properties must be supported by validation evidence
for the relevant release, operating system, and deployment mode.

The V7 Coordination Broker remains subject to independent
security review and cross-platform acceptance.

No security certification, complete isolation guarantee,
or universal secret-protection guarantee is claimed here.

## Coordinated Disclosure

Vulnerability reports should be reviewed privately before
public disclosure.

Confirmed remediation information may be published through
GitHub Security Advisories and official project releases.

Acknowledgement deadlines, disclosure timelines, and
maintenance commitments require an approved support policy.
